The `User/` and `Studies/` folders are grouped under `data/` in this proposal
to make the data boundary explicit. They retain their separate JSON files.

## Responsibilities and dependencies

- `public/index.html` contains the page and references Bootstrap from a CDN,
  `public/css/style.css`, and `public/js/script.js`.
- `public/js/script.js` implements category selection, study details, login,
  and the admin user/study forms. It calls relative `/api/...` endpoints, so
  the frontend must continue to be served from the same origin as Express.
- `public/css/style.css` contains the project-specific styling layered over
  Bootstrap.
- `server/server.js` hosts the Express API, serves `public/`, and reads or
  writes user and study JSON files.
- `data/User/*.json` stores user names, password hashes, and roles. These files
  must remain outside the public static directory.
- `data/Studies/*.json` stores one study per file. Each file contains its
  title, category, overview, recruiting status, and details.
- `package.json` and `package-lock.json` stay in the root so npm commands and
  dependency installation have a single project entry point.
- `node_modules/` is generated from the package files and should not be
  reorganized manually.
- `SPEC.md` stays in the root because `AGENTS.md` currently tells contributors
  to read it there. `README.md` also stays in the root as the standard project
  entry point.

## Required updates during an approved migration

Moving files would require coordinated path changes; moving files alone would
break the application:

1. Change the `start` script in `package.json` to run `server/server.js`.
2. Update the server's project, static, user-data, and study-data paths.
3. Configure Express to serve only `public/`, not the project root.
4. Update the stylesheet and JavaScript paths in `public/index.html`.
5. Keep the `/api/...` URLs on the same origin so browser requests still reach
   the Express server.
6. Update `AGENTS.md` if any documented file locations change.
7. Verify login, admin account editing, study creation/editing, category
   filtering, and study details after the move.

## Current consistency notes

- `SPEC.md` lists authentication, study editing, and an Express backend as
  features, but its "Out of scope" section also excludes those features.
- `AGENTS.md` says to use only plain HTML/CSS/JavaScript and lists the three
  frontend files at the root, while the actual project also uses Express and
  npm. These instructions should be reconciled if the proposed layout is
  approved.
